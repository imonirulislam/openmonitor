# packages/db — Database

Drizzle ORM + Postgres. Single source of truth for schema and types.

## Conventions

- **Schema lives in `src/schema.ts`** — one file, organized by domain section. Keep it that way until it grows past ~600 lines.
- **All identifiers are `uuid` defaults**, generated by Postgres (`defaultRandom()`). Never accept client-supplied IDs.
- **Timestamps are `timestamp({ withTimezone: true })`** with `.defaultNow()` for `created_at`. `updated_at` is set by application code on writes.
- **Enums are pg enums** (not text + check constraints) — they show up nicely in Drizzle Studio and force migration when the set changes.
- **Soft-delete is not used.** If we need it later, add `deleted_at` rather than a boolean.
- **Snake_case at the DB layer, camelCase in TS.** Drizzle's `casing: "snake_case"` handles the mapping (`packages/db/src/client.ts`).
- **Cross-table foreign keys always set `onDelete`.** Default to `cascade` for child tables, `set null` for nullable references (e.g., `created_by`).
- **JSONB columns get a TypeScript type via `.$type<T>()`.** Don't store untyped JSON.

## Adding a new table

1. Add the `pgTable` to `src/schema.ts` near related tables.
2. Add `relations(...)` if it has FKs.
3. Add inferred types to `src/types.ts`.
4. Run `bun run db:generate` from the root — Drizzle writes a new file under `drizzle/`.
5. Review the generated SQL. Hand-edit if needed (e.g., partial indexes, custom defaults).
6. Run `bun run db:migrate` to apply.

## Adding a new enum value

Postgres can't drop or reorder enum values. To add: edit the `pgEnum(...)` array in `schema.ts`, generate, migrate. To remove a value: write a manual migration that recreates the type.

## Migrations

- Migrations are checked in under `drizzle/`.
- Never edit a migration that has shipped to any environment. Add a new one.
- For data migrations, write a `.sql` file by hand inside `drizzle/` and add it to `_journal.json`, OR write a one-shot tsx script under `scripts/` and run it manually after deploy.

## Events outbox

`events` is the outbox consumed by `apps/notifier`. Producers (web admin, checker) **must** insert into `events` in the same transaction as the state change that triggered them. If you write a new mutation, ask: "does this fire a notification?" If yes, emit an event row.

## Seed

`src/seed.ts` is idempotent — re-running it should not duplicate rows. Use `onConflictDoNothing` or `onConflictDoUpdate` for every insert.
